# Real public-caption pilot: keyword stage

**Status, 2026-10-02:** The caption-only keyword screen has run on the [23 locked original-Reel captions](../data/real_public_reels_caption_development_v1.jsonl). This document preserves the **keyword stage**; the later [two-stage AI run and comparison](public_caption_ai_pilot_v1.md) are reported separately. The [case-level keyword output](public_caption_keyword_v1.jsonl), [machine-readable summary](public_caption_keyword_v1_summary.json), [source-selection record](public_caption_source_selection_v1.md), and [checksum manifest](../data/real_public_reels_caption_development_v1_manifest.json) make this stage inspectable.

| Keyword suggestion | Count | What it means in this screen |
|---|---:|---|
| `PASS` | 11 | A listed acceptable disclosure example was found literally in the captured caption. This is **not** approval of placement, claims, the video, or private terms. |
| `HUMAN_REVIEW` | 4 | No listed acceptable example was found, but a listed insufficient example such as `#gifted` was found. Confirm relationship and other disclosure surfaces. |
| `UNKNOWN` | 8 | No listed marker was found; material connection and video disclosure are unverified. Absence of a marker is not treated as a violation. |
| `FLAG` | 0 | This conservative literal screen makes no violation accusation from caption text alone. |

All 23 `full_review_status` values are `UNKNOWN`. There are no independent compliance labels for these posts, so accuracy, precision, recall, and confusion matrices are **not calculated**. These cases are not pooled with the 60 fictional development cases. The sample is purposive and skewed toward disclosure and gift wording; these counts are not prevalence estimates.

The keyword path only checks the rulebook's listed disclosure patterns under `CH-DISC-01`. It deliberately does not call the old full-script baseline with empty scenes. It cannot understand unlisted equivalents, the meaning of a generic gift phrase, contextual claims, actual mobile caption placement, video speech or overlays. For example, plain `Gifted` without a hashtag does not match the current `#gifted` literal pattern. A `PASS` from this screen is therefore only a positive marker observation; a reviewer must not promote it to a full-video pass.

The case-level output makes those limits concrete. `REAL-11`, `REAL-15` and `REAL-16` contain gift wording without the listed hashtag and receive `UNKNOWN` from the literal screen; this is a vocabulary gap, not evidence that the posts lack any disclosure. `REAL-02` places its listed partnership hashtag after endorsement wording, but mobile fold and prominence were not checked. `REAL-20` receives a marker `PASS` while also expressing first-hand product experience; the literal disclosure screen does not verify use. These examples explain why the AI method and a human reviewer may raise different questions on the same caption, and why neither can decide the full video from this dataset.

Run the free stage from the repository root with `python scripts/evaluate_public_captions.py`. The script verifies the locked source checksum and row order before screening, retains existing outputs without overwriting them, and shows a no-call API status. The two-stage AI path is implemented separately in [`src/public_caption_reviewer.py`](../src/public_caption_reviewer.py), with the exact prompt version `public-caption-2026-10-02-v1`. The [prompt manifest](../data/public_caption_prompt_manifest_v1.json) locked both instructions, response schemas, model and rulebook before the first paid public-post request. The paid run later saved raw caption suggestions, evidence, uncertainty, token usage, cost and latency in [separate AI results](public_caption_ai_v1.jsonl). The paid cost ceiling was US$1.50; the conservative preflight was US$0.827944 using the [OpenRouter GPT-6 Sol standard rates](https://openrouter.ai/openai/gpt-6-sol) checked on 2026-10-02. The saved usage-based estimate was US$0.181154, not a provider invoice.

The project owner ran `& .\scripts\run_public_caption_ai.ps1` in their own PowerShell because the key was unavailable to the Codex process. The helper uses the existing environment key if present, or prompts for it without echoing, then removes a newly prompted process key afterward. It does not write the key into the repository. Re-running the script with an existing AI output intentionally stops before another paid request unless an explicit resume or new output path is selected.
