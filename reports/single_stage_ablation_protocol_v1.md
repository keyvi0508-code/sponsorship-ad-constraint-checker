# One-stage versus two-stage design comparison

**Pre-run design record:** The paid run was subsequently completed on 2026-10-02. See the [measured comparison](single_stage_ablation_results_v1.md); the prospective wording below is retained to show what was specified before that run.

This is a **planned exploratory ablation**, not a completed result. The original two-stage reviewer first extracts evidence, then judges it under the CHANEL rulebook. The alternative in [`src/single_stage_reviewer.py`](../src/single_stage_reviewer.py) uses one OpenRouter request with the same model, review fields, operational rule boundaries, and decision JSON schema; it replaces the instruction to use Level 1 evidence with an instruction to find and verify evidence directly. Its [prompt manifest](../data/single_stage_prompt_manifest_v1.json) locks the exact alternative before the first ablation call.

The comparison set is the frozen 30-case synthetic extension, because its [two-stage case-level outputs](ai_evaluation_extension_v2.jsonl) already exist. `python scripts/evaluate_single_stage_ablation.py` makes **no API call** and prints the planned cost and call count. With a local API key, `python scripts/evaluate_single_stage_ablation.py --run-api --confirm-paid-run` runs the one-stage alternative, saves every case, and compares verdicts, usage and estimated cost against the saved two-stage run. From the user's own PowerShell, `& .\scripts\run_single_stage_ablation.ps1` supplies a hidden key prompt if needed. The dry-run preflight estimated a conservative US$0.601014 for 30 one-call cases at the recorded standard rates; the hard run ceiling is US$1.50. Resume checks prevent silent overwrites or an unbounded run. No result is claimed until the paid run completes.

The design comparison can answer whether one stage gives similar decisions with fewer requests on these **constructed cases**. It cannot prove that two stages cause better real-world judgement: the one-stage prompt was devised after the two-stage outputs were inspected, the cases and labels are project-authored, and model responses vary across runs. Cost and latency should be reported alongside any verdict difference. A stronger causal comparison would pre-register both prompts and run them on a fresh, independently labelled set with repeated trials or paired human adjudication.
